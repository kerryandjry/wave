# Local Development Instructions

## Repository workflow

- This checkout is for personal development and experiments. Do not open an upstream PR unless the user explicitly asks.
- `origin` (`kerryandjry/wave`) is the writable personal fork. Treat `upstream` (`iree-org/wave`) as read-only.
- Work on the current feature branch (normally `gfx90a`) and push completed commits to the matching branch on `origin`.
- Before changing code, run `git fetch --all --prune`, inspect `git status --short --branch`, and compare the branch with both its `origin` tracking branch and `upstream/main`.
- Never discard local changes. Keep commits focused, verify them, then push. Do not force-push or rewrite published history unless explicitly requested.
- Generated benchmark data, profiler output, binaries, and plots belong under `artifacts/` and stay untracked. Commit reusable scripts and documentation only.

## GPU execution

GPU work must run on the MI210 host `dg-mem`; the login host does not provide a ROCm GPU.

The active checkout is:

```text
/gpfs/home/yukalee/wave
```

Start GPU commands with:

```bash
ssh dg-mem 'bash -lc "module load rocm/5.2.0 >/dev/null 2>&1 && export LD_LIBRARY_PATH=/gpfs/software/python/3.11.2/lib:$LD_LIBRARY_PATH && cd /gpfs/home/yukalee/wave && <COMMAND>"'
```

For Python Wave or `wave_runtime` tasks, also activate the MI210 environment when it is available:

```bash
source /gpfs/home/yukalee/.venvs/wave-mi210/bin/activate
```

That path is a symlink into `/gpfs/scratch`. Verify it on `dg-mem` before use; if it is unavailable, report the broken environment instead of silently running with `/usr/bin/python`. Standalone HIP/rocBLAS/hipBLASLt work can use the installed ROCm 7.2.2 tools directly, for example `/opt/rocm-7.2.2/bin/hipcc`.

Before a benchmark, verify:

```bash
/opt/rocm-7.2.2/bin/rocm-smi --showproductname --showuse --showmemuse
```

Use a fixed device such as `HIP_VISIBLE_DEVICES=0`, record shape, dtype, warmup count, iteration count, timing method, GPU architecture, and ROCm version, and validate correctness when the benchmark path supports it.

## GEMM experiment conventions

- The current MI210 comparison uses `gfx90a`, `f16 x f16 -> f32`, square `M=N=K` sizes 4096, 8192, and 16384, with 10 warmups and 50 measured iterations.
- Wave artifacts are generated by `scripts/run_gemm.py`; LLVM/WaveASM rocmasm results are measured by `scripts/compare_rocmasm_perf.py`.
- `scripts/benchmark_blas_gemm.cpp` measures rocBLAS and hipBLASLt with HIP events around GPU work. Keep library setup and hipBLASLt heuristic selection outside the timed region.
- Use `scripts/plot_gemm_artifact_perf.py --library-results <results.jsonl>` for the WaveASM/rocBLAS/hipBLASLt comparison plot.
- Existing profiler and artifact summaries are evidence. Do not overwrite them without preserving the command and parameters used for the replacement run.
